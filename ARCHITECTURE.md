# 7BS — Архитектура

SaaS CRM для веломастерских с интеграцией поставщиков комплектующих.

Документ — живая спецификация. Кода здесь нет, только проектные решения, модель данных и план. Обновляется по мере развития проекта.

**Связанные документы:** модель данных — [`prisma/schema.draft.prisma`](prisma/schema.draft.prisma) · контракты API — [`API.md`](API.md).

---

## 1. Суть продукта

Мульти-тенантная **двусторонняя SaaS-площадка** между **мастерскими** и **поставщиками** запчастей.

Ключевой принцип: **поставщик — это тенант внутри системы**, а не внешний интегратор. Поставщик загружает свой Excel-прайс, его номенклатура попадает в общий каталог, а заказы от мастерских приходят прямо в его панель (+ e-mail-уведомление). Никаких внешних API на оформление заказа не требуется.

### Зафиксированные решения

| Развилка | Решение |
|---|---|
| Модель поставки | SaaS, мульти-тенант (десятки мастерских/поставщиков) |
| Фокус | Сбалансированно: заказ-наряды (CRM) + подбор/заказ запчастей |
| Канал оформления заказа | «A» — заказ в панели поставщика + e-mail (поставщик внутри системы) |
| Данные поставщиков | Excel-файлы, парсинг с маппингом колонок в общую БД |
| Частота/размер прайсов | Раз в несколько месяцев, тысячи строк → импорт синхронный, очереди не нужны |
| Нагрузка | Низкая → без микросервисов, очередей, event-driven |

### Вне скоупа (отложено)

Интеграции с 1С / онлайн-кассой / платежами · клиентский портал · велосовместимость деталей · кросс-нормализация каталога между поставщиками · полноценный складской учёт с движениями.

## 2. Технический стек

Выбран **Вариант 3 — модульный монолит (отдельный API + SPA)** ради долгосрочной сопровождаемости.

- **Монорепо:** **pnpm workspaces** — `apps/api`, `apps/web`, `packages/shared`.
- **Backend:** NestJS (TypeScript), модульная структура.
- **Frontend:** Next.js (React) + **Tailwind CSS** + **shadcn/ui** (компоненты копируются в проект, полный контроль).
- **БД:** PostgreSQL + Prisma (миграции, типобезопасность, удобный маппинг импорта).
- **Общие типы/DTO:** `packages/shared` (Zod-схемы + выводимые типы) — единый контракт фронта и бэка.
- **Auth:** JWT (access + refresh) на стороне NestJS.
- **Хостинг (free-tier):** API → Railway/Render/Fly.io · БД → Neon · фронт → Vercel · файлы прайсов → Cloudflare R2.

## 3. Роли и доступ

| Роль | Тенант | Назначение |
|---|---|---|
| `SUPER_ADMIN` | — (системный) | Управление тенантами, создание админов мастерских/поставщиков |
| `SUPPLIER_ADMIN` | supplier | Управление поставщиком, импорт прайса, заказы |
| `SUPPLIER_STAFF` | supplier | Обработка входящих заказов, смена статусов |
| `WORKSHOP_ADMIN` | workshop | Сотрудники, клиенты, заказ-наряды, история заказов |
| `MECHANIC` | workshop | Заказ-наряды, поиск по каталогу, оформление заказов |

### Мульти-тенантная изоляция

1. JWT несёт `userId`, `tenantId`, `role`.
2. **Request-scoped TenantContext** извлекается из токена.
3. **Prisma middleware** автоматически добавляет `where: { tenantId }` ко всем тенант-привязанным запросам — защита от утечки данных между тенантами на уровне ORM, а не вручную в каждом сервисе.
4. `@Roles(...)` + `RolesGuard` на эндпоинтах.
5. `SUPER_ADMIN` идёт по отдельному пути в обход тенант-фильтра.

## 4. Доменная модель

| Сущность | Ключевые поля | Связи |
|---|---|---|
| **Tenant** | `id`, `type: workshop\|supplier`, `name` | 1—N User |
| **User** | `id`, `tenantId?`, `role`, `email`, `passwordHash` | N—1 Tenant |
| **ImportTemplate** | `supplierId`, `columnMapping(JSON)` | N—1 Tenant(supplier) |
| **ImportBatch** | `supplierId`, `fileRef`, `importedAt`, `rowsOk/rowsErr` | 1—N Product |
| **Product** | `supplierId`, `sku`, `name`, `price`, `stockQty`, `attrs(JSON)` | N—1 Tenant(supplier) |
| **Client** | `workshopId`, `name`, `phone` | 1—N Bike, 1—N WorkOrder |
| **Bike** | `clientId`, `brand`, `model`, `notes` | N—1 Client |
| **WorkOrder** | `workshopId`, `clientId`, `bikeId`, `mechanicId`, `status` | 1—N WorkOrderLine |
| **Order** | `workshopId`, `supplierId`, `status`, `createdBy` | 1—N OrderItem |
| **OrderItem** | `orderId`, `productId`, `qty`, `priceSnapshot` | N—1 Product |
| *(отложено)* **StockItem** | `workshopId`, `productRef`, `qty` | — |

### Инварианты модели

- **Один Order = один поставщик.** Корзина мастера автоматически разбивается по поставщикам — каждый получает свой заказ в своей панели.
- **`priceSnapshot` обязателен** в OrderItem: прайс может обновиться, но цена в оформленном заказе фиксируется на момент оформления.
- **ImportTemplate на каждого поставщика** (маппинг «колонка файла → поле»). В MVP стартуем с **одного генерального поставщика** с уже отработанным форматом Excel — для него заводим один фиксированный ImportTemplate. Гибкий редактор маппинга и подключение остальных поставщиков — следующая итерация.

### Статусные машины (черновик)

- **Order:** `NEW → ACCEPTED → ASSEMBLED → SHIPPED` (+ `CANCELLED`).
- **WorkOrder:** `NEW → IN_PROGRESS → WAITING_PARTS → DONE → CLOSED`.

## 5. Карта экранов по ролям (MVP)

| Роль | Экраны |
|---|---|
| SUPER_ADMIN | Список тенантов · создание мастерской/поставщика · создание их админов |
| SUPPLIER_ADMIN/STAFF | Загрузка Excel + маппинг колонок · свой каталог · входящие заказы + смена статуса |
| WORKSHOP_ADMIN | Сотрудники · клиенты · все заказ-наряды · история заказов поставщикам |
| MECHANIC | Заказ-наряд (создать/вести) · поиск по каталогу всех поставщиков · корзина → оформить заказ · статусы заказов |

Адаптив под телефон обязателен (мастеру нужен и ПК, и телефон в цеху).

## 6. Модули NestJS

- **identity** — auth, пользователи, роли, тенанты.
- **catalog** — товары поставщиков, поиск/фильтр по всем прайсам.
- **import** — загрузка Excel, ImportTemplate (маппинг), парсинг → Product.
- **crm** — клиенты, велосипеды, заказ-наряды.
- **inventory** — склад мастерской *(отложено в MVP)*.
- **orders** — заказы мастерской → поставщику, статусы. Уведомление в MVP — только в панели поставщика (e-mail отложен).

## 7. Скоуп MVP (цель ~1 месяц)

**Внутри:** тенанты+роли+супер-админ · импорт Excel **одного генерального поставщика** (фиксированный шаблон) · каталог и поиск · заказ поставщику + его панель (уведомление в панели) · базовый заказ-наряд (клиент/велосипед/статус) · привязка позиций заказа к наряду · адаптив.

**Снаружи (буфер по срокам):** e-mail-уведомления · гибкий редактор маппинга + подключение остальных поставщиков · складской учёт с движениями (пока поле «в наличии») · велосовместимость · аналитика · клиентский портал · кросс-нормализация каталога.

## 8. План по неделям

| Неделя | Цель | Содержание |
|---|---|---|
| 1 — Фундамент | «Скелет ходит» | Монорепо, NestJS+Next skeleton, Postgres+Prisma, JWT-auth, Tenant/User/Role, RolesGuard + Prisma-tenant-middleware, супер-админ создаёт тенантов. **Сразу настроить деплой.** |
| 2 — Каталог + импорт | Прайс → БД → поиск | Загрузка Excel генерального поставщика, фиксированный ImportTemplate, парсинг (`exceljs`), Product, ImportBatch, каталог с поиском у мастера. |
| 3 — Заказы | Сквозной поток | Корзина → разбивка по поставщикам → Order/OrderItem с priceSnapshot, инбокс поставщика, статусная машина (уведомление в панели, без e-mail). |
| 4 — CRM + полировка | Заказ-наряды и релиз | Client, Bike, WorkOrder со статусами, связь позиций заказа с нарядом, адаптив, баг-фикс, прод-деплой, буфер. |

## 9. Принятые решения по развилкам

1. **Маппинг Excel** — стартуем с одного генерального поставщика (отработанный формат → фиксированный шаблон). Гибкий редактор маппинга — следующая итерация.
2. **E-mail** — в MVP не делаем; уведомление о заказе только в панели поставщика.
3. **UI-кит** — shadcn/ui + Tailwind CSS.
4. **Монорепо** — pnpm workspaces.
